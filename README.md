# Задание 1: разделение ответственности

Исходник: https://gitverse.ru/50jun/web-standartization/content/master/createOrder.js

## Три абстракции

- `domain/Order.js` — предметная область: заказ, расчёт стоимости позиций и скидка 5% при сумме строго больше 10 000. Не зависит от HTTP, SQL и почты.
- `orderRepository.save(order)` — контракт сохранения. `storage/SqlOrderRepository.js` реализует его через переданный клиент базы данных.
- `orderNotifier.notify(email)` — контракт уведомления. `notifications/EmailOrderNotifier.js` реализует его через переданный SMTP-клиент.

Контракты описаны через JSDoc в `createOrder.js`. В JavaScript для подмены реализации достаточно объекта с соответствующим методом; отдельные базовые классы не нужны.

`makeCreateOrder` создаёт HTTP-обработчик с переданными зависимостями. Он разбирает запрос, отклоняет пустую корзину, создаёт заказ, сохраняет его, отправляет уведомление и формирует ответ. `index.js` соединяет обработчик с конкретными реализациями.

## Подключение

```js
const { buildCreateOrder } = require('./index');
const createOrder = buildCreateOrder({ db, smtp });
// Зарегистрируйте createOrder в существующем HTTP-приложении.
```

Как в исходнике, `req.body` должен быть JSON-строкой, а `req.user` — содержать `id` и `email`. Клиенты `db` и `smtp` предоставляет приложение. Если middleware уже разбирает JSON, вместо `JSON.parse(req.body)` нужно использовать `req.body`.

## Проверка

Node.js 18 или новее; установка зависимостей не требуется:

```sh
npm test
```

Проверяются расчёт, граница скидки, пустая корзина, SQL-параметры, письмо, порядок действий и ошибки внешних зависимостей.

Поведение исходника сохранено: ошибки разбора JSON, базы и почты передаются вызывающему коду; ошибка почты возникает после сохранения заказа. Дополнительная валидация, округление денежных сумм, транзакции и повторная отправка писем в это задание не добавлены.
